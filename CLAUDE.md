# CLAUDE.md

Notes for Claude Code sessions working in this repository.

## What this is

MyAnimelist.NET: a .NET 10 client library for the MyAnimeList API v2 (`https://api.myanimelist.net/v2/`), with OAuth2 PKCE login. Author: Peter Vietense (SoftThorn), MIT license, GitHub `Insire/MyAnimelist.NET`. User-facing docs are in [README.md](README.md).

## Layout

- `src/` is the library (`MyAnimelist.NET.csproj`, namespace `MyAnimelist.NET`).
  - `RegistrationExtensions.cs`: `AddMyAnimelist(ClientConfiguration)` is the DI entry point. It registers `IAuthCache`/`IBrowserLoginHandler` with `TryAdd` (overridable), a typed `HttpClient` for `MyAnimelistService`, and `MyAnimelistLoginHandler` (DelegatingHandler that adds the Bearer token).
  - `MyAnimelistService.cs` is the facade. Property names don't match the generated class names:
    - `Catalog` → `Client`: anime and manga search/details, `UsersAsync`
    - `Anime` → `AnimeClient`: ranking, season, suggestions, list status patch
    - `Manga` → `MangaClient`
    - `Forum` → `ForumClient`
    - `Users` → `UsersClient`: animelist, mangalist
    - `Login` → `LoginClient`
  - `AutoGeneratedClient.cs` is **generated by NSwag. Do not hand-edit it.** Change `assets/` (templates or spec) and regenerate.
  - `CustomizedModels.cs` holds hand-written list/paging models (`AnimeList`, `MangaList`, `UserAnimeList`, ...) that the generated code uses.
  - `JsonSerializerSettings.cs` implements the generated clients' `UpdateJsonSerializerSettings` partials and sets `NumberHandling.AllowReadingFromString`, because MAL sends `statistics.status.*` as strings.
  - `Authentication/`:
    - `LoginClient`: PKCE flow with `code_challenge_method=plain` and an `HttpListener` on `RedirectUrl`.
      - `StartOAuthFlowAsync` returns `bool` and validates `state`.
      - It awaits the listener and `IBrowserLoginHandler.Handle` at the same time, because the Playwright handler only completes after the redirect has been answered.
      - It skips the browser when `TokenClient` already has a valid token or can refresh one.
    - `TokenClient` (singleton): owns `https://myanimelist.net/v1/oauth2/token`.
      - It covers the code exchange and the refresh grant, using its own named HttpClient (`TokenClient.HttpClientName`) with no auth handler, so refreshing can't recurse.
      - It stamps `AuthResponse.ExpiresAt` using the injected `TimeProvider`.
      - `GetValidTokenAsync` refreshes once the token is within 1 minute of expiry, behind a `SemaphoreSlim`, so concurrent callers trigger a single refresh. A token without `ExpiresAt` is used as-is.
      - `MyAnimelistLoginHandler` calls it before every request.
    - `AuthCache`: in-memory `IMemoryCache` only, so tokens are lost on restart. There is no cache expiry, because the refresh token must outlive the access token. `SaveAsync` overwrites.
    - `BrowserLoginHandler`: `Process.Start` with the shell
    - `ClientConfiguration`/`ClientConfigurationOptions`: the options variant is nullable, for config binding
- `assets/`: `MyAnimelist.NET_OpenApiSpec.json` (scraped from the MAL Redoc page), `MyAnimelist.NET_Config.nswag`, `Templates/*.liquid` (custom NSwag templates).
- `build/`: Cake Frosting build (`build.ps1`/`build.sh` → `dotnet run --project build/Build.csproj -- <args>`). Tasks are in `build/Tasks`, paths in `build/Util/Constants.cs`. Output goes to `tmp_build/`.
  - `Default`: clean, update `SharedAssemblyInfo.cs`, test, coverage/Codecov, pack, push. It pushes locally to `E:\Drop\NuGet`, or to nuget.org only on Azure Pipelines with `NUGETORG_APIKEY` set.
  - `UpdateOpenApiSpec`: re-scrapes the spec with HtmlAgilityPack and Jint, then runs nswag to regenerate the client.
    - Before writing the spec, it patches places where MAL's spec doesn't match the live API: path parameter names that don't match the path template (`user_id` on `/users/{user_name}`), and `ForumTopic.data`/`ForumTopicData.poll`, which are objects rather than arrays, with `close` sent as `closed`. Add new spec fixes there, not only in the JSON file, or the next scrape reverts them.
    - To regenerate from the existing spec without re-scraping, run `dotnet tools/.store/nswag.consolecore/<version>/nswag.consolecore/<version>/tools/net10.0/any/dotnet-nswag.dll run ./assets/MyAnimelist.NET_Config.nswag`.
  - The `.nswag` config must keep `generateImmutableArrayProperties`/`generateImmutableDictionaryProperties` set to `false`. With `true`, collections are `{ get; } = null` and System.Text.Json silently skips them.
- `tests/` holds two xUnit v3 projects on Microsoft.Testing.Platform. Each has its own `Traits.cs` (`TestCategory`).
  - `MyAnimelist.NET.UnitTests`: **no network access allowed.**
    - `TokenClientTests` uses a stub HTTP handler and a fixed `TimeProvider`.
    - New tests that don't call MAL go here.
  - `MyAnimelist.NET.IntegrationTests`: **live tests against the real MAL API**, using Verify and Playwright.
    - `OAuth/OAuthFlowTestFixture` is an assembly fixture and a Playwright `PageTest`. It implements `IBrowserLoginHandler` to fill in the MAL login form automatically.
    - Config comes from user secrets (Debug, `UserSecretsId cc5b08ee-...`) or environment variables. It needs `ClientConfiguration:{ClientId,RedirectUrl}` and `MalAuthSettings:{UserName,Password}`. Secrets are set up on the user's machine.
    - The csproj sets `SolutionDir`/`SolutionName` because two `.slnx` files confuse Verify's auto-discovery.
    - There is one test class per facade property (`CatalogTests`, `AnimeTests`, `MangaTests`, `UsersTests`, `ForumTests`). `Fields.cs` holds `fields` values that request every mapped property. Each test snapshots its response in one of two ways (`Snapshots/`):
      - `SnapshotSettings.ForStableEntity()` snapshots real values for entities that no longer change (anime 1, manga 1, forum boards), with counters like mean, rank, members, statistics and recommendations scrubbed. MAL's CDN switches the same picture between `.jpg` and `.webp` from one request to the next, so image URLs end in `.{image}`. This is done by a `Uri` converter, because Verify's line scrubbers don't reach `Uri` values.
      - `ModelShape.Of(response)` snapshots only the structure, for live lists whose content changes. Each property becomes its type name and collections merge into one element shape. A field that stops deserializing disappears, and a field MAL adds lands in `AdditionalProperties` (`[JsonExtensionData]`), so both show up as a diff.
    - The test account's manga list is empty, so the `MangalistAsync` snapshot is `{}`. A snapshot of `@me` or a ranking can change when the account's list changes (`my_list_status` appears) or when a ranking gains or loses optional fields. Re-accept a snapshot only after checking that the diff is data, not a broken model.
    - `*.received.*` files are gitignored. Set `DiffEngine_Disabled=true` to stop Verify from opening a diff tool.
- `Directory.Build.targets` links `SharedAssemblyInfo.cs` through `$(MSBuildThisFileDirectory)`, so projects can sit at any depth.
- Central package management is in `Directory.Packages.props`; `build/` has its own. Versioning uses Nerdbank.GitVersioning (`version.json`) with plain SemVer, staying on 0.x for now (decided 2026-10-17, see `versioning.md`).
- Package metadata: shared fields (authors, license, repository, copyright) are in `Directory.Build.props`, package-specific ones (description, tags, `PackageReadmeFile`) in `src/MyAnimelist.NET.csproj`. The README is packed and shown on nuget.org, so its links to repo files use absolute `github.com/.../blob/main/...` URLs. The package icon is still missing; the owner will choose one.
- CI is **Azure DevOps** (`azure-pipelines.yml`), not GitHub Actions (owner's choice, 2026-10-17). It runs `./build.ps1` on pushes to `main`/`v*.*`, with `pr: none` because fork PRs get no secrets. Secrets come from the variable group `MyAnimelist.NET` and are mapped to env vars in the YAML. Every pipeline build of those branches pushes to nuget.org.
- Release notes (added 2026-10-17): the Cake `ReleaseNotes` task (`build/Tasks/ReleaseNotesTask.cs`, parsing and rendering in `build/Util/ReleaseNotes.cs`) runs `git log <last v* tag>..HEAD` and groups conventional commits. Breaking changes come from `type!:` or a `BREAKING CHANGE:` footer, and highlights from `Release-Note:` footers. A count line is always included.
  - Output goes to `tmp_build/results/release-notes.md` (Markdown with commit links) and `release-notes.txt` (plain text, internal changes left out).
  - `BuildAndPack` depends on it and passes `-p:PackageReleaseNotesFile`, which `src/MyAnimelist.NET.csproj` reads into `PackageReleaseNotes`.
  - `TagRelease` (a dependency of `Push`) creates a lightweight tag `v{SemVer2}` and pushes it, but only after `PushRemote` actually pushed (`context.PackagesPushedToNuGet`). On Azure, this relies on `persistCredentials: true` and a service connection with write access.
  - Git is called through `context.RunGit`/`RunGitOrThrow` (the CLI, not Cake.Git).
  - `./build.ps1 --target ReleaseNotes` previews the notes locally. There were no tags as of 2026-10-17, so the first release lists the whole history.
  - Commit messages feed this task, see [Commit messages](#commit-messages).
- The README has an "AI assistance" section. Claude-assisted commits carry the `Co-Authored-By: Claude ...` trailer (see [Commit messages](#commit-messages)).

## Commands

- Build: `dotnet build MyAnimelist.NET.slnx`
- Test:
  - Unit tests only (no secrets): `dotnet test --project tests/MyAnimelist.NET.UnitTests/MyAnimelist.NET.UnitTests.csproj`
  - Integration tests: `dotnet test --project tests/MyAnimelist.NET.IntegrationTests/MyAnimelist.NET.IntegrationTests.csproj`
  - Both: `dotnet test --solution MyAnimelist.NET.slnx`. A bare `dotnet test` at the root fails, because there are two `.slnx` files.
  - `global.json` sets `test.runner = Microsoft.Testing.Platform`, so use MTP/xUnit v3 options such as `--filter-trait`, `--coverage` and `--report-xunit-trx`, not VSTest's `--filter`, `--collect` and `--logger`.
  - The Cake `Test` task uses the same options in Release. User secrets only load in Debug, so Release needs environment variables.
- Full pipeline: `./build.ps1`. Regenerate the client: `./build.ps1 --target UpdateOpenApiSpec`
- Environment: Windows, PowerShell. Python is **not** installed, so don't use it for scripting.
- **Line endings:** the repository stores every file with **LF**. `core.autocrlf=true` checks files out as CRLF, and git converts them back when you add them.
  - Never convert files to CRLF yourself, even though `.editorconfig` says `end_of_line = crlf`.
  - On 2026-10-17, files converted with `sed 's/\r*$/\r/'` were committed as CRLF (through Fork). Git then showed the whole of `build/BuildContext.cs` and `build/Util/Constants.cs` as changed, and a follow-up commit had to restore LF.
  - Before finishing, check that `git diff --numstat` shows only the lines you meant to change.
  - To check how a committed file is stored, run `git show HEAD:<path> | file -`. If it reports CRLF, fix the working copy with `sed -i 's/\r$//' <path>`.

## Commit messages

These rules apply to every commit message you write: suggested messages at the end of a session, and messages the owner's git client (Fork) asks you to generate for staged changes. The Cake `ReleaseNotes` task builds the release notes and the NuGet package notes from these messages, so the format matters.

Fork runs Claude Code (`%userprofile%\.local\bin\claude.exe`) in the repo folder with a fixed prompt: "Generate commit message for staged changes", subject under 50 characters (soft) and 70 (hard), wrap at 72, no "generated" footer. Fork for Windows has no documented way to edit that prompt (the Mac version can, under Integration preferences, since 2.64), so these rules live here and add to it. When Fork asks for a message, output only the message: no explanation, no code fence, no list of changed files.

Format ([conventional commits](https://www.conventionalcommits.org)):

```text
<type>(<optional scope>)<optional !>: <subject>

<body>

<footers>
```

- **Type** decides the release-notes section:
  - User-facing (shown on nuget.org): `feat` (Features), `fix` (Bug fixes), `perf` (Performance), `chore(deps)` (Dependencies, for package or tool updates), `docs` (Documentation).
  - Internal (GitHub release only, left out of the package notes): `build`, `ci`, `test`, `refactor`, `style`, `chore`.
  - When a commit mixes kinds, pick the type that matters most to library users. For example, a fix plus the test that covers it is `fix`, not `test`.
- **Scope** (optional) is the area, in lowercase: `auth`, `anime`, `manga`, `forum`, `users`, `catalog`, `client` (generated code / spec), `build`, `tests`. Leave it out when no single area fits.
- **Subject:** imperative and lowercase (`add`, `fix`, `remove`, not `Added`/`Fixes`), no trailing period, under 50 characters if possible and never over 70, including the prefix. It appears as-is in the release notes, so write it for library users and name the public API when it changed.
- **Body:** wrap at 72 characters. Say what changed and why, not file by file.
- **Breaking changes** are any change to the public API of `src/` that can break a consumer's build or behavior: renamed or removed members, changed signatures or defaults, or a raised target framework.
  - Mark them with `!` after the type/scope.
  - Add a `BREAKING CHANGE: <what consumers have to change>` footer. Write the footer as migration advice; it appears under the breaking changes heading.
  - Changes to `build/`, `tests/` or docs are never breaking.
- **`Release-Note: <one sentence>`** footer: add it only for changes a library user should hear about first: new capabilities, notable fixes, breaking changes. It lands in the release's Highlights. Write a complete sentence for users. Internal changes never get one.
- **Footer order:** `BREAKING CHANGE:`, then `Release-Note:`, then `Co-Authored-By:` last, each separated by a blank line. A footer can continue on the next line; it ends at a blank line or the next footer.
- **`Co-Authored-By: Claude <model> <noreply@anthropic.com>`:** add it when you wrote or changed code or docs in the commit (the README's AI assistance section depends on it). Leave it out when you only wrote the message for changes the owner made.

## Known quirks / open issues (as of 2026-10-16)

- `RedirectUrl` must end with `/` because it is used as the `HttpListener` prefix.
- The package is not published on NuGet yet (confirmed by the user).
- There's no 401 retry: if MAL revokes a token before `ExpiresAt`, requests fail until the next login.
- MAL's spec gives `UsersClient.AnimelistAsync`/`MangalistAsync` no `fields` parameter, so `list_status` can't be requested and only `node` (id, title, main_picture) comes back (as of 2026-10-17).
- Verified on 2026-10-17: the Cake targets `HtmlReport`, `BuildAndPack` and `UpdateOpenApiSpec`. `Default` was not run, because it pushes the package to `E:\Drop\NuGet`.
  - Release tests need the secrets as environment variables (`ClientConfiguration__ClientId` and so on). You can export them from `dotnet user-secrets list` in the integration test project.
- `tmp_build/results/reports/cobertura/Cobertura.xml` actually contains Microsoft's XML coverage format (`dotnet-coverage merge -f xml`), not Cobertura. ReportGenerator reads it fine.
- Cake process calls go through `context.RunProcess(...)` (`build/Util/BuildContextExtensions.cs`), which throws on a non-zero exit code. Don't call `StartProcess` directly.
  - The only exception is `TestTask`. A test failure sets `context.TestsAreFailing` and the build keeps going, so the coverage reports still get generated.
  - The pushes and the Codecov upload skip when that flag is set, and `BuildLifetime.Teardown` then fails the build. Cake exits with 127 in that case.
- `BuildLifetime.Setup` takes `IsPublicRelease` from Nerdbank's `VersionOracle.PublicRelease`, so `version.json`'s `publicReleaseRefSpec` (`main` and `v<major>.<minor>` branches) is the single source of truth. To change which branches are public releases, edit `version.json`, not the build.
  - It used to compare the branch with `"master"`; fixed on 2026-10-17.
  - `BuildAndPackTask` passes the flag as `-p:PublicRelease`, so public-release builds get versions without the commit-hash suffix.
